# 이슈 진행 기록

개발자 지시부터 AI 제안·개발자 결정·수정·테스트·검수·최종 판단·재수정까지 한 작업의 흐름을 보관한다. 버그뿐 아니라 기능·기획·기술 검증·문서 작업도 포함한다.

공개 저장소에도 이 실제 기록을 같은 경로·회차·내용으로 반영하고 제한 파일·민감 위치만 제외한다. 별도 AI 협업 소개나 공개용 결과물로 다시 작성하지 않는다. 개발자 직접 수정과 AI 수정, 피드백 재수정, 실제 이슈 해결·검증 주체를 그대로 구분한다.

## 파일과 식별자

- 실제 기록: `Records/IR-YYYYMMDD-NNN_subject.md`. 같은 날짜의 기존 번호를 확인해 새 번호를 부여한다.
- [작성 양식](Issue_Record_Template.md)을 복사해 사용한다. 한 논리적 작업은 한 문서에서 회차를 누적한다. 사소한 후속 수정마다 새 문서를 만들지 않는다.
- GitHub Issue가 없어도 로컬 IR-ID로 시작하고 `원격 Issue 미생성`을 적는다. 이후 실제 Issue/PR/commit 링크만 추가한다.
- 현재 실제 기록: [IR-20261105-001 커밋·협업 과정 규칙 정비](Records/IR-20261105-001_commit-workflow.md).
- [IR-20261105-002 조사 범위·출처·콘셉트 재검토](Records/IR-20261105-002_mobile-concept-research.md).
- IR-20261105-003 S3 선정·Cuisineer 기반 구체화 (공개 제외).

## 단계

- [IR-20261106-003 비공개 원본·공개 자동 반영](Records/IR-20261106-003_public-sync.md).

`요청 → AI 제안 → 개발자 결정 → 실제 수정 → 테스트·검수 → 최종 결정`.

문제·FAIL·추가 지적이 나오면 `재수정 사유 → 새 제안/결정 → 수정 → 재검증 → 최종 결정` 회차를 추가한다. 수행하지 않은 단계는 미실행·미확인으로 남기며 빈 단계를 만들기 위해 대화를 유도하지 않는다.

| 단계 | 기록할 사실 |
|---|---|
| 요청 | 개발자가 해결하려는 문제·포함/제외·완료 조건 |
| AI 제안 | AI 분석·선택지·추천·미확인 가정 |
| 개발자 결정 | 실제 채택·반려·수정 지시·지적과 이유, 발언/문서 근거 |
| 실제 수정 | AI 수정·지적 반영 AI 수정·개발자 직접 수정·혼합을 파일/변경별 구분 |
| 테스트·검수 | 실행자·검토자, 환경·기대/실제·결과, 지적 사항 |
| 최종 결정 | 개발자 수락·보류·반려·재수정 지시와 적용 범위 |
| 재수정 | 원인·이전 회차·변경·같은 조건의 재검증·후속 결정 |

개발자가 지시한 목표와 AI가 정한 세부 구현은 구분한다. 테스트 PASS를 개발자 최종 수락으로 해석하지 않는다. 새 지시가 없다고 최종 승인으로 간주하지 않으며, 별도 승인 없이 처리 가능한 로컬 작업은 끝까지 완료한다.

## 중복과 공개

- 이 문서는 과정의 원본이다. 커밋·PR에는 해당 변경만 요약하고 IR 경로·회차를 연결한다.
- ADR은 기술 결정 상세, Test Log는 실행 상세, Troubleshooting은 심층 원인 분석의 원본으로 유지한다. 여기에는 결론·해당 문서 링크만 적는다.
- [협업 목록](../Workflow/Collaboration_Log.md)은 찾아보기로 사용한다. 같은 대화를 여러 문서에 복제하지 않는다.
- 실제 수행·결정이 확인된 내용만 한국어로 요약하고 원시 대화·비밀·개인정보를 복사하지 않는다. 기록 규칙 (공개 제외)과 공개 기준 (공개 제외)을 따른다.
