## 책임·대안

기존 CookingUi/ContentUi처럼 런타임 uGUI를 생성하는 방식과 새 Canvas/프리팹을 씬에 직렬화하는 방식을 비교했다. AI는 기존 생성 방식·직접 참조를 선택했다. 씬/프리팹 재연결·패키지 추가 없이 MainSceneLoader가 TutorialUi를 한 번 추가한다. 범용 이벤트 버스/새 저장 서비스를 도입하지 않는다. 이 구현 선택은 별도 기술 채택 승인으로 기록하지 않는다.

TutorialUi는 시작 시 공통 시스템/UI/카메라를 캐시하고 지역이 바뀔 때만 해당 포차·숲 입구·주문 목록을 검색한다. 입력→기존 게임 판정→실제 상태 관찰→단계 변경→GameSave.RequestSave 순이다. 터치 표시/마스크는 입력/보상 처리를 대신하지 않는다. TutorialInputMask가 화면 Image의 raycast를 대상 UI 사각형 또는 실제 월드 대상 collider에만 통과시킨다. 하단 소형 안내·좌상단 수량·대상 강조/터치 표시를 공통 Canvas 최상단에 둔다. 조이스틱/상호작용/메뉴/조리/완성/주문/성장 버튼의 기존 입력을 사용한다.

Growth.Tutorial은 기존 Cooking 캡처의 JSON 독립 사본에 포함되며 로컬/클라우드 경로를 새로 만들지 않는다. 단계 외 첫 유형/배정 수·테이블/포장 정상 판매·대상 SaveId/음식·Tip 페이지, NoticeClosed/NoticeStep·JoystickTouched·HarvestGoals를 보존한다. 활성 상태 범위를 검증한다. 저장 포맷 schema3/콘텐츠4는 유지하고 선택 필드를 추가했다. 실제 파일 처리/체크섬/백업/계정/세션 정책은 변경하지 않는다.

기존 저장에 필드가 없거나 Enabled=false이면 안내를 시작하지 않는다. 원래 해금 소유/골드/레벨은 보존하고 Growth.ApplyUnlocks에서 조건 충족분과 재료 숲만 추가한다. 새 무료 강화 플래그 대신 도토리 현재Lv1 판정으로 한 번만 무료 처리한다. 단계 진입 때 저장을 요청하며 앱 중단 저장은 기존 GameSave 경로를 사용한다. OS 강제 종료 전 미확정 저장 완료를 보장하지 않는다.

복원 시 조리/완성/선택 상태를 관찰해 이미 끝낸 행동을 반복시키지 않는다. 대상 주문이 사라지면 아직 판매하지 않은 유형으로 다시 연결하고 성장 패널이 닫혔으면 열기부터 안내한다. 판매 완료 직후 단계 저장 전 중단도 유형별 완료 상태로 복구한다. 두 유형 모두 정상 제공 후 원래 배정 로직으로 돌아간다. 주문 실패 시 미완료 유형을 재시도한다.

## 카메라·시간·설정

회전/크기를 바꾸지 않고 카메라 위치만 이동한다. 종료/지역 전환/메뉴 중단 시 로컬 위치와 이동 게이트를 복구한다. 검수 후속으로 WorldClock.TutorialPaused와 고객/NPC/대기열의 해당 보류 조건을 제거했다. 튜토리얼은 시간/손님 진행을 보류하지 않는다. 기존 일시정지/포커스/전환/세션 차단은 계속 우선한다. SceneLoadManager.SetTutorialMovementBlocked는 이동만 제어하고 SetUiOpen(owner, bool)은 창별 소유자 집합으로 일반 UI 이동 잠금을 유지한다. canSimulate/월드 시계와 이동 조건을 분리한다. 피로 회복 정책을 새로 변경하지 않는다.

수정 위치: TutorialUi.ShowStep/Continue/RefreshFocus(문구·닫힘·입력 유도), `_panSeconds`(3초+도착1초), ForestRegrowth.GetHarvestYield/HarvestTarget의 Ingredient/YieldCount/IsCollected(실제 필드 목표/완료), Growth.FoodRequirement/Cost(음식 조건/무료강화). 고정5개 설정은 제거했고 현재 숲1 배치의 총 도토리7/버섯6이 동적 목표가 된다. 목표는 재료별 실제 yield 합계, 진행은 수집 완료한 대상의 yield 합계다. 골드/가방 재고나 이전 탐험에서 모은 재료로 완료를 대체하지 않는다. 지역 재진입 시 재생성된 대상에서 다시 집계하고 재접속 시에는 복원된 수집 상태를 읽는다. 다른 맵/드롭 변경 시 동적 집계와 완료를 재검증한다.

로그: 기존 `[Gameplay]`의 tutorial_initialize/tutorial_step/tutorial_customer/food_unlock/forest_unlock/growth_purchase, `[UI]` 초기화 오류를 확인한다. 매 프레임 검색/로그를 추가하지 않는다. 도움말 재열람은 이번 안내 모듈에 포함하지 않는다. 영상은 로컬 브라우저 정책으로 재생하지 못했으며 사용자 서술을 구현 기준으로 사용했다.

기존 RecipeData.RequiredLevel/PurchaseCost와 Catalog.ForestLevels/ForestCosts는 SO 직렬화/기존 도구 호환을 위해 보존했으나 현행 음식·숲 해금 판정/비용에는 사용하지 않는다. 포차 전체레벨·골드/테이블 비용과 음식 강화 가격 곡선은 기존 값을 유지한다.

## 2026-11-17 검수 회차8 — 목적지 간 이동·카메라 표식 유지

TutorialUi의 포차/숲 입구 카메라 단계는 월드 타깃/waypoint를 함께 지정한다. LateUpdate는 카메라 이동/확인창 때문에 목적지 표식을 숨기지 않으며 화면 밖/뒤의 목적지는 가장자리로 제한한다. 표식은 이동 목적을 알려주며 카메라/확인 대기의 실제 이동 허가를 바꾸지 않는다.

숲 내부 Pan(center,8,_forestOverviewScale)은 위치와 orthographicSize를 같은 진행률로 보간한다. `_forestOverviewScale=1.6`은 줌 아웃 초깃값, `_panSeconds=3`과 도착1초는 기존 값이다. RestoreCamera는 정상 완료/중복 연출 교체/일시정지·세션 차단·전환/비활성에서 위치와 원래 크기를 복구한다. 연출 완료 전 중단되면 기존 재시도 정책을 유지한다.

PlayerWorldInteraction의 `_tutorialInteractionRange=.9`와 GetInteractionRange를 CanInteractWith에서 공용 사용한다. TutorialUi는 거리 안내 때 tutorial=true를 요청하고 실제 입력 대상은 SetTutorialTarget에 지정된 경우 자동으로 같은 좁은 범위를 쓴다. 일반/채집은 기존1.8이다. 포차 앞 InteractionPoint와 기본 앞줄 중앙 Seat2의 XZ 거리는2.51로, 기존 반경1.8 두 개는 겹치지만0.9 두 개는 겹치지 않는다. 일반 반경이나 씬 배치를 바꾸지 않고 튜토리얼의 이동 구간만 명확히 했다.

수락 후 GuideMarket은 좁은 반경 밖에서 이동을 풀고 표식을 포차 앞으로 바꾼다. 도착하면 이동 정지/상호작용 열기를 유도한다. 완성 픽업 후 GuideWorldAction은 손님까지 이동을 풀며 도착 후 서빙 상호작용을 유도한다. `[Input] tutorial_route result=moving/arrived`는 대상/근접 상태 변화에만 출력해 잠금 전환 근거를 남긴다. Play로 확인한 결과는 아직 아니며 [IR 회차8](../Issue_Records/Records/IR-20261117-004_business-rework.md)·검증 회차5 (공개 제외)를 따른다.

## 2026-11-17 검수 회차9 — 대상 주변/방향·초기 텍스트 준비

현행 거리 기준은 테이블 중심/포장 선두 손님/포차 외곽이며 앞 절의 좌석·고정 포차 앞 앵커 기준을 대체한다. CanInteractWith는 일반1.8/튜토리얼0.9 거리와 실제 VisualRoot 전방 반각55도를 함께 확인한다. 가까워도 아직 바라보지 않으면 이동/회전을 허용하고, 도착+바라보기 후 이동을 잠가 상호작용을 유도한다. 안내 대상 지정과 실제 수락/서빙은 같은 판정을 사용한다. 일반 후보는 방향 일치 우선·유사 방향 거리 우선으로 고른다.

사용자가 모바일1~18/그 외 기능 정상 보고를 제공했다. 이번 거리·방향/버튼/성능 보완은 그 뒤 수정이며 실제 터치·성능 재검증 전이다. [IR 회차9](../Issue_Records/Records/IR-20261117-004_business-rework.md)·검증 회차6 (공개 제외).
