# 테스트·실행 기록 규칙

## 상태와 책임

| 상태 | 의미 |
|---|---|
| PASS | 명시한 조건에서 실제 실행했고 기대 결과를 만족 |
| FAIL | 실제 실행했으며 기대 결과와 다름. 재현·실제 결과 필요 |
| NOT RUN | 실행하지 못함·환경 없음·기준 미확정. 이유와 다음 행동 필요 |
| N/A | 적용되지 않음. 기능/플랫폼 조건과 이유 필요 |

차단 상태는 별도 원인으로 적고 실행 결과는 `NOT RUN`으로 둔다. 자동화·Editor·에뮬레이터 결과를 Android 실기기 결과로 옮기지 않는다. 사용자 제공 결과는 제공자·환경·자료를 명시한다.

## 작업별 최소 검증

| 변경 | 검증 |
|---|---|
| 문서만 | 로컬 링크·경로·용어·양식 상태·사실 일치 검사 |
| 게임 규칙 | 컴파일, 정상/실패/경계·재시작; 필요한 EditMode/PlayMode 테스트 |
| UI·입력 | 실제 터치, 안전영역·비율·UI 겹침·중복 입력 |
| 저장·복귀 | 신규/기존/손상 데이터, 중단·재실행·복구 정책 |
| 씬·프리팹 | GUID/참조, 씬 전환·재진입, Build Settings |
| 패키지·설정 | 복원·컴파일·Android 빌드·영향 기능 회귀 |
| 성능 변경 | 동일 빌드 조건의 전후 측정·장시간 실기기 비교 |

작은 변경에 구현을 그대로 흉내 내는 테스트를 양산하지 않는다. 기존 테스트와 실제 위험에 맞는 확인을 우선한다. 위 표의 미실행 항목을 숨기지 않는다.

## 기록

- 최종 결과: `Docs/Test/Logs/YYYY-MM-DD_subject.md`. 같은 날 반복하면 실행 번호를 붙인다.
- [Test Log Template](../Test/Test_Log_Template.md)을 사용하고 날짜(KST)·실행자·환경·커밋·빌드·기대/실제·상태·자료 위치를 채운다.
- 최초 커밋 이전에는 `commit=없음`과 기준 파일/변경 설명을 적는다. 해시를 만들어 내지 않는다.
- 앱 버전·Version Code·APK 이름/보존·권장안과 실제 산출물·실행자별 기록은 빌드 규칙 (공개 제외)을 원본으로 따른다. 같은 버전명의 다른 빌드를 혼동하지 않도록 해당 규칙의 필수 식별/검증 필드를 연결한다.
- 스크린샷·영상은 핵심 조건·시간대를 적고 비밀·개인정보를 정제한다. 대형 원본은 승인된 저장 위치에 두고 필요한 기록만 링크한다.
- 과거 FAIL을 지우지 않는다. 수정 PR과 같은 조건의 재검증 기록을 연결한다.

## 결함과 완료

심각도: Blocker(진행/설치 불가·데이터 유실), Major(핵심 기능 손상), Minor(우회 가능), Trivial(표현). 우선순위 P0/P1/P2와 심각도를 구분한다.

Issue Done은 해당 완료 조건을 실제 만족할 때만 설정한다. 필수 실기기 테스트가 NOT RUN이면 구현 완료와 검증 대기를 구분하고 전체 Done으로 닫지 않는다. 정해진 기준 안에서 테스트가 통과하면 불필요하게 반복하지 않는다.

프로젝트 Editor 검사/구성 도구를 사용할 때는 사용 안내·현재 호환성 (공개 제외)을 먼저 확인한다. 검사 도구 수정 시 해당 도구 안내의 절차·변경 대상·검증 결과/기준도 함께 갱신한다. 안내 작성·소스 정적 확인은 도구 실행 PASS가 아니며 기존 테스트 제외는 계속 따른다.
