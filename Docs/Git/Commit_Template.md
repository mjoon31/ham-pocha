# 커밋 작성 규칙

기존 프로젝트의 `type(scope): 변경 내용` 형식을 유지한다. Unity 모바일 개발에 맞는 영역을 사용한다.

## Summary

```text
type(scope): [contribution] 변경 내용
```

| type | 의미 |
|---|---|
| feat | 사용자 기능 추가 |
| fix | 오류 수정 |
| refactor | 동작 변경 없는 구조 개선 |
| chore | 프로젝트·패키지·리소스 설정 |
| docs | 문서·규칙·기획 |
| test | 테스트·실행 결과 기록 |

scope: `gameplay`, `input`, `ui`, `audio`, `data`, `save`, `performance`, `android`, `project`, `research`, `planning`, `architecture`, `workflow`, `site`. 미채택 네트워크·백엔드 영역을 기본값으로 넣지 않는다.

## 변경 경위 구분

Summary에 아래 태그 하나를 넣는다. 실제 작성자와 결정 경위를 함께 표시하기 위한 프로젝트 규약이다.

| contribution | 의미 | 실제 수정자 |
|---|---|---|
| ai | 개발자 요청 범위에서 AI가 분석·구현·문서를 작성 | AI |
| directed | 개발자의 구체적 선택·지적·검수 의견을 받아 AI가 변경·재수정 | AI |
| manual | 개발자가 코드·설정·문서를 직접 수정 | 개발자 |
| mixed | AI와 개발자 수정이 하나의 안전한 변경 단위에 함께 포함 | 본문에 파일/변경별 구분 |
| review | 제안·결정·테스트·검수·최종 판단 기록만 변경 | 본문에 실제 기록자·실행자 구분 |

단순히 AI에 작업을 지시한 것은 `ai`다. 개발자가 특정 대안을 고르거나 문제를 지적했고 AI가 이를 반영했다면 `directed`다. 개발자가 직접 편집한 사실이 있을 때만 `manual`로 쓴다. 테스트 기록은 `review`로 쓸 수 있지만 테스트에 따른 코드 수정은 수정 경위에 맞는 태그를 사용한다.

## Description — 필수

GitHub Desktop은 Summary/Description을 각각 입력한다. 한 줄로 구분되지 않는 수행·판단·검증을 아래 항목으로 남긴다. 해당 사실이 없으면 `없음`, 확인할 수 없으면 `미확인`으로 표시한다.

```text
기록: Docs/Issue_Records/Records/<실제 파일> / 실제 Issue·PR
요청·제안: 요청 요지 / AI 제안·선택지 / 기록 내 단계·회차
개발자 판단: 채택·반려·지적 내용과 이유 또는 미확인
개발자 작업내용: 직접 수행한 코드/Inspector/콘솔 설정·빌드·테스트·검수 등 또는 없음/미확인
실제 수정: AI / 개발자 / 혼합 — 각각 변경한 파일·내용
AI 작업내용: 실제 분석·코드/설정/문서 수정·진단·검사 등 또는 없음/미확인
검증: 실행자 / 환경 / PASS·FAIL·NOT RUN / 실제 기록
후속: 최종 판단 또는 재수정 사유·다음 회차
```

### 판단과 작업 주체의 필수 분리

2026-11-14 개발자 지시. 실제 커밋951293c에서 사용한 구분을 이후 모든 커밋안·최종 본문에 적용한다. 제목 태그만으로 수행 주체를 대신하지 않는다.

| 필수 항목 | 기록할 내용 |
|---|---|
| 개발자 판단 | 실제 대안 채택·반려·지적·피드백과 확인된 이유 |
| 개발자 작업내용 | 개발자가 직접 한 파일/Inspector/외부 콘솔 설정·빌드·기기 조작·테스트·검수. 직접 편집과 실행을 구분 |
| 실제 수정 | 커밋 대상 파일·변경의 실제 편집자를 AI/개발자/혼합으로 요약 |
| AI 작업내용 | AI의 실제 분석·작성·수정·진단·자동 검사·기록 정리. 개발자 결과를 기록한 것과 AI 직접 실행은 구분 |

- 개발자의 지시·승인은 판단이다. AI가 대신 편집한 파일을 개발자 직접 수정으로 적지 않고, 개발자의 직접 빌드·실기기·콘솔 작업을 AI 작업으로 돌리지 않는다.
- 확인된 직접 작업이 없으면 **없음**, 수행 여부를 확인할 수 없으면 **미확인**을 적는다. 항목을 생략하거나 추정 작업을 만들지 않는다. 외부 에셋 제작자와 AI의 등록 작업도 구분한다.
- 개발자가 테스트만 한 경우 작업내용·검증에 적되 manual 코드 수정으로 자동 분류하지 않는다. 제목 태그는 기존 변경 경위 정의를 따른다.
- 해당 커밋에 포함되는 일만 짧게 적고 실제 IR 회차·검증 링크를 연결한다. 같은 설명을 각 항목에 반복 복사하지 않는다.
- 기존 기록/요청·제안/개발자 판단/실제 수정/검증/후속6항목은 유지하며 **개발자 작업내용·AI 작업내용**을 추가한다. 공개 커밋과 PR 요약에도 구분을 보존하고 승인된 민감 정보만 가린다.
- 이후 작성에 적용한다. 과거 커밋 재작성·가짜 중간 커밋·빈 커밋은 만들지 않는다.
예시 메시지(실제 구현·테스트 이력이 아님):

```text
feat(input): [ai] 요청한 드래그 입력 구현
fix(input): [directed] 개발자가 지적한 UI 관통 입력 차단
fix(ui): [manual] 개발자가 버튼 배치 직접 조정
fix(save): [mixed] 저장 판정과 개발자 수정 UI 연결
test(android): [review] 실기기 재검증 결과 기록
docs(planning): [review] 개발자 콘셉트 선택과 반려 이유 기록
```

## 역할별 공용 메모에서 커밋안으로 연결

- 각 작업 대화는 AGENTS의 공용 기록 규칙 (공개 제외)에 따라 메모에 **개발자 판단·개발자 작업내용·AI 작업내용**을 각각 남긴다. 파일/범위와 IR 회차·검증 링크로 연결하고, 없는 항목은 없음·근거가 부족하면 미확인으로 적는다.
- Git·공개 관리 대화는 대상 작업 메모와 실제 최신 diff·연결 기록을 대조하여 필수 본문에 반영한다. 판단·직접 편집·설정/빌드/검증 실행을 구분하고 제목 태그를 결정한다. 전체 대화 원문을 검색하거나 복사하지 않는다.
- 메모를 덮어쓰더라도 해당 작업의 미커밋 기여를 누락하지 않는다. 이미 반영된 작업을 새 커밋 기여로 중복 기재하지 않도록 기준 커밋·반영 상태를 확인한다. 메모와 실제 근거가 다르면 추정으로 귀속하지 않고 해당 부분을 확인한다.
- 메모는 협업 참고이며 커밋·푸시·공개 승인이 아니다. 관련 없는 진행 중 변경은 제외하고 기존 승인·Public Sync 절차를 따른다. 로컬 메모 자체는 커밋·공개하지 않는다.

## 커밋 분리·이력 보존

- 한 커밋에는 하나의 목적·핵심 scope 하나를 담는다. 안전하게 분리할 수 있으면 AI 초안, 개발자 지적 반영, 개발자 직접 변경, 검증 기록을 별도 커밋으로 구분한다.
- 한 파일에 섞인 수정은 내용을 확인해 분리한다. 분리가 참조·빌드·의도를 깨면 `mixed`와 본문으로 구분한다. 과거 작업을 추정해 가짜 중간 커밋으로 재구성하지 않는다.
- 제안·결정·검수는 실제 기록 파일이 바뀐 경우에만 커밋한다. 단계를 채우기 위한 빈 커밋은 만들지 않는다.
- Git 작성자·커미터만으로 실제 코드 수정자를 판단하지 않는다. AI가 개발자 계정으로 커밋해도 내용은 AI 수행으로 기록한다. 작성자 정보를 조작하지 않는다.
- 재수정 커밋은 같은 이슈 기록의 회차·지적/실패·직전 변경을 연결한다. FAIL과 반려 이유를 지우지 않는다.
- 병합은 GitHub 규칙 (공개 제외)에 따라 구분을 보존한다. 실제 commit/push·병합은 해당 지시 범위에서만 수행한다.

과정 원본은 [이슈 기록 운영](../Issue_Records/README.md)을 따른다. 작업 전체 원문을 각 커밋 본문에 복사하지 않고 해당 회차와 변경만 요약한다.

완료 보고에 기능별 원본 파일·제목·필수 본문을 한 번만 제안한다. 공개본은 같은 커밋 단위·제목·본문·경위 태그를 사용하며 민감 경로/링크만 기계적으로 가린다. 별도 공개 커밋 메시지를 작성·승인받지 않는다. [공개 동기화 흐름](Public_Sync_Workflow.md)에 따라 승인 후 비공개 dev commit/push부터 공개 반영 확인까지 진행한다. 신규 파일/범위 변경은 명시해 먼저 승인받는다. 피드백은 원본 기록의 다음 회차와 실제 재수정 커밋으로 남기고 공개에도 동일하게 연결한다.
