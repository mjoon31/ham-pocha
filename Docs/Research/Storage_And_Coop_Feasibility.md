# 저장·협동 방식의 초기 검토

확인일: 2026-11-05 KST. 공식 문서 조사 결과이며 Unity 2022.3.62f3 프로젝트에서 연동·실행한 결과가 아니다. 기술 채택은 미결정이다.

## DB 없는 저장

| 방식 | 가능한 일 | 비용·설정 | 제한 |
|---|---|---|---|
| 단판·저장 없음 | 한 판의 상태만 메모리에 유지 | 계정·클라우드 저장 서비스 불필요 | 앱 종료·새 판에서 초기화 |
| 로컬 파일 | 도감·해금·소량 진행을 JSON 등 파일로 저장 | 자체 DB·로그인·클라우드 사용료 없이 구현하는 대안 | 기기 변경·삭제 시 복구/공유는 별도 해결 필요 |
| Google Play Games Saved Games | 플레이어 진행 파일을 Google 서버에 보관·동기화 | 저장 데이터 요금 무료. Play Console·PGS 설정·Unity 플러그인·인증/테스트 필요 | 파일당 3MB 제한, 충돌 해결·오프라인 동기화·실패 처리 필요 |

Google 계정 로그인 자체가 게임 데이터를 저장하지는 않는다. 별도 저장 API와 게임 데이터 읽기·쓰기 구현이 필요하다. Saved Games를 사용하면 별도 소유 DB 서버 없이 진행 파일을 저장하는 설계를 검토할 수 있다. 실시간 멀티 동기화 기능과는 구분한다.

근거: [Google Saved Games](https://developer.android.com/games/pgs/savedgames), [Unity Saved Games 안내](https://developer.android.com/games/pgs/unity/saved-games). 공식 안내는 저장 파일당 3MB와 저장 데이터 비과금·오프라인 후 동기화를 설명한다. 사용자 계정의 준비 상태·해당 Unity 버전과 선택할 플러그인 조합은 미검증이다.

Play Console 계정이 없다면 [공식 등록 안내](https://support.google.com/googleplay/android-developer/answer/6112435/)에 미화 25달러 일회성 등록비가 있다. 따라서 서비스 저장 요금 무료를 전체 준비 비용 0원과 동일하게 표현하지 않는다. 이 조사에서 계정 생성·결제·연동은 수행하지 않았다.

## 저장 없는 협동

- 영구 저장을 없애도 방 생성·참가·실시간 상태·동기화·이탈·앱 중단/복귀·재시작 처리는 필요하다.
- 같은 네트워크에서의 로컬 협동과 서로 다른 장소에서의 인터넷 협동은 다른 요구다. LAN에서만 확인한 결과를 원격 인터넷 지원으로 보고하지 않는다.
- 인터넷 협동은 호스트 방식에서도 NAT/방화벽 등을 고려해야 한다. 중계 서비스를 채택하면 무료 한도·이후 비용을 확인한다. [Unity Relay 설명](https://docs.unity.com/relay/relay-servers), [UGS 요금](https://unity.com/products/gaming-services/pricing)을 참고했으며 현재 SDK를 선택하지 않았다.
- 작은 테스트 범위에서 비용을 줄일 수 있는 가능성과 무제한 무료 운영은 구분한다. 계정·리소스 생성·유료 기능 활성화는 수행하지 않았다.

초기 후보 A는 2인·맵 1개로 접속/판정 PoC를 먼저 한다. B/C는 저장 없는 단판으로 먼저 플레이 감각을 검증하고, B에서 장기 도감이 꼭 필요할 때만 저장 연동 범위를 다시 정한다.

## S3 선정 이후의 진행 유지 제안

2026-11-05: 솔로 S3가 선정되었고 음식·숲의 레벨 해금이 추가되었다. 위 A/B/C 언급은 초기 후보 이력이다. 현재는 GDD 저장 제안 (공개 제외)에 따라 로컬 XP·창고·안전 체크포인트 유지를 우선 검토한다. 계정·자체 DB 없이 가능하나 SDK/형식/복구 정책은 아직 채택하지 않았다. 클라우드가 필요해지면 공식 조건을 재확인한다. 저장안이 결정되기 전 과거 단판 초기화를 최신 확정 규칙으로 사용하지 않는다.
