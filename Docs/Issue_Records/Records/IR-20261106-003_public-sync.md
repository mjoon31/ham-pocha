## 1. 개발자 요청과 결정

비공개 ham-pocha-dev에서 결과·기능별 커밋안 제시 → 개발자 선택 → 비공개 dev commit/push → 필요한 공개 자료만 공개 dev 별도 commit. 이후 비공개 PR의 검토·병합에 맞춰 공개 PR/main도 자동 진행하고 피드백을 같은 흐름에 연결하도록 요청했다.

공개 범위 질문에 개발자는 비공개 작업 중 필요한 내용만 공개 전용 폴더에 복사해 반영하도록 선택했다. 이어 다음 세부를 확정했다.

- `[비공개 로컬 경로]`가 유일한 Unity 개발 원본이다. 공개 `[비공개 로컬 경로]`는 자동 생성 결과물만 보관한다.
- 개별 허용 목록과 Public 자료를 사용한다. 승인된 원본 C#은 Source로 직접 추출하고 공개용 중복 개발을 하지 않는다.
- 비공개 dev 작업·승인 뒤 commit/push, Actions 공개 dev 반영, 개발자의 비공개 PR 검토·병합 뒤 main 자료 자동 공개를 수행한다.
- 별도 공개 Git 이력을 사용하고 내부 메시지·Git 객체·AGENTS·skills·MCP·Unity 원본 에셋/씬/프리팹·인증정보·비공개 문서는 제외한다.
- 신규 공개 파일·범위 변경은 먼저 승인받는다. 기존 양쪽 main/dev·이력을 보존하고 다른 소스 폴더를 건드리지 않는다.
- 비밀/제외/브랜치/삭제/중복 검증과 최소 권한 App 또는 Fine-grained Token·Secrets를 사용한다. 기존 진행분을 중복 구축하지 않는다.

이 요청은 자동화의 상시 운영 범위를 확정한다. 이번 실제 파일별 커밋안·초기 공개 문서에 대한 최종 승인은 별도로 남기며, AI가 최종 수락을 대신 기록하지 않는다.
