숲과 마을을 오가며 포차 영업에 필요한 재료를 수집하고, 손님의 주문에 맞춰 조리하고 서빙합니다. 자정이 되면 영업을 마감하고, 집에서 피로를 회복하며 다음 날을 준비합니다. 영업으로 얻은 골드와 경험치는 음식 강화와 새로운 탐험 지역·레시피 해금에 쓰입니다.

## 숲에서 포차까지, 햄스터의 하루

**숲 탐험·재료 수집 → 재료 입고 → 조리·서빙 → 판매·성장 → 마감·수면**

- **계절 숲 탐험**에서는 미니맵으로 출입구와 수집 대상을 확인합니다. 밤에 몬스터가 공격해 오면 채집을 더 이어갈지, 모은 재료를 가지고 돌아갈지 판단합니다.
- **실내 조리와 서빙**은 공유 냉장고에서 재료를 꺼내 조리대에 넣는 것부터 완성된 음식을 손님에게 직접 건네는 것까지 이어집니다.
- **야시장 영업**은 화로에서 꼬치를 구워 진열하고 자동으로 판매하는 방식입니다. 판매 수익과 경험치로 음식을 강화하고, 새 메뉴와 화로, 탐험 지역을 엽니다.
- **집 꾸미기**에서는 창고에 보관한 가구의 위치와 방향을 바꾸고, 벽 마감을 바꿔 공간을 꾸밉니다.

## 플레이를 받치는 구조

- **씬 전환과 영업 진행.** 공통 시스템이 있는 Main 씬을 유지하고 집·마을·숲을 필요에 따라 불러옵니다. 실내외 영업 중에는 마을과 포차 씬을 함께 두고 카메라와 조작 대상을 전환해, 다른 공간의 조리와 손님 행동도 이어지도록 구성했습니다.
- **레시피·성장 데이터.** 레시피에 재료와 아이콘을 연결하고 콘텐츠 카탈로그에서 메뉴 해금과 강화를 관리합니다. 조리·메뉴 선택·강화 화면이 같은 데이터를 참조합니다.
- **탐험과 미니맵.** 이동과 상호작용은 Unity Input System으로 처리합니다. 숲에 다시 들어오면 채집 대상과 몬스터를 재배치하고, 같은 방문의 저장을 이어갈 때는 수집 상태를 복원해 미니맵에도 반영합니다.
- **가구 배치와 계정별 저장.** 배치 전 격자의 점유와 입구·침대 접근 경로를 확인합니다. 로컬 JSON과 Firebase Authentication·Cloud Firestore를 연결해 계정별 진행을 저장하고, 저장 ID로 주문 상태와 가구 배치를 복원합니다.

## AI 작업의 범위를 정하고 결과를 검수하는 방식

게임의 방향과 구현 우선순위, 결과의 채택 여부를 직접 결정했습니다. AI에는 조사, 코드 수정, 에디터 도구 제작과 검사를 맡기고, 실제 플레이로 결과를 확인한 뒤 후속 수정을 지시했습니다.

1. **작업 지시.** 목표로 하는 플레이 결과, 유지할 규칙, 변경 범위와 완료 기준을 함께 전달했습니다. 야시장 영업을 변경할 때는 재고 차감, 진열과 판매, 기존 저장에 미치는 영향까지 검사 항목에 포함했습니다.
2. **변경과 검증 기록.** 요청, AI 제안, 개발자 결정, 수정과 재검증을 같은 이슈에 이어 기록했습니다. 커밋에는 개발자가 직접 수행한 작업, AI가 수행한 변경과 검증 환경을 구분해 남겼습니다.
3. **도구 제작과 공개 동기화.** 저장 ID 부여, 프리팹 격자 배치, 레시피 참조 검사처럼 반복되는 작업을 에디터 도구로 만들었습니다. 공개 자료는 승인한 파일과 변경 이력을 GitHub Actions로 선별해 동기화합니다.
